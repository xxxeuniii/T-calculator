# T-Calculator 前端开发规范

## 1. 目录结构规范

### 1.1 整体目录结构

```
web/src/
├── App.js                  # 应用入口组件（仅路由、状态管理，不含页面业务逻辑）
├── AppStyles.js            # App.js 对应的样式文件
├── calculator.js           # 业务计算逻辑（纯函数）
├── klineCount.js           # K线相关计算逻辑（纯函数）
├── utils.js                # 通用工具函数（格式化等）
├── styles/                 # 全局样式
│   ├── theme.js            # 主题色板（palette）
│   └── global.js           # 全局复用样式（可选）
└── components/             # 组件目录
    ├── common/             # 通用基础组件
    │   ├── Field/
    │   │   ├── index.js    # 组件逻辑
    │   │   └── styles.js   # 组件样式
    │   ├── StepField/
    │   ├── Segment/
    │   ├── Metric/
    │   └── ProfitMetric/
    ├── TradeCalculator/    # 股票做T计算器
    │   ├── index.js
    │   └── styles.js
    ├── ContractCalculator/ # 合约移动止盈止损
    │   ├── index.js
    │   └── styles.js
    ├── ContractRoiScreen/  # 止盈止损回报率
    │   ├── index.js
    │   └── styles.js
    ├── Mt5LiquidationScreen/ # MT5强平价计算
    │   ├── index.js
    │   └── styles.js
    ├── KlineCountScreen/   # 数K线时间计算
    │   ├── index.js
    │   └── styles.js
    ├── SessionHoursScreen/ # 盘口时段
    │   ├── index.js
    │   └── styles.js
    └── HistoryScreen/      # 历史记录
        ├── index.js
        └── styles.js
```

### 1.2 文件夹命名规则

- 组件/页面文件夹名：**大驼峰（PascalCase）**，与组件导出名一致，例如 `TradeCalculator/`
- 通用基础组件放 `components/common/`
- 业务页面放 `components/` 下

### 1.3 文件命名规则

| 文件 | 命名 | 说明 |
|------|------|------|
| 组件逻辑 | `index.js` | 文件夹内唯一入口，`export default ComponentName` |
| 组件样式 | `styles.js` | 使用 `StyleSheet.create`，`export default styles` |
| 根组件样式 | `{ComponentName}Styles.js` | 如 `AppStyles.js` |
| 主题色板 | `theme.js` | 放在 `styles/` 下 |
| 计算逻辑 | 语义化命名.js | 如 `calculator.js`、`klineCount.js` |

## 2. 组件开发规范

### 2.1 组件结构模板

每个组件文件夹严格遵循 **一个逻辑文件 + 一个样式文件**：

```javascript
// components/Example/index.js
import React from "react";
import { View, Text } from "react-native";
import styles from "./styles";         // 样式从同级 styles.js 引入
import Field from "../common/Field";   // 同级兄弟组件用相对路径
import { formatUsdt } from "../../utils"; // 工具函数用向上相对路径

export default function Example({ prop1, prop2 }) {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Hello</Text>
    </View>
  );
}
```

```javascript
// components/Example/styles.js
import { StyleSheet } from "react-native";
import palette from "../../styles/theme";   // 所有颜色从主题引入

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: palette.paper,         // 禁止硬编码颜色
  },
  title: {
    color: palette.ink,
    fontSize: 16,
    fontWeight: "800",
  },
});

export default styles;
```

### 2.2 组件设计原则

1. **单一职责**：一个组件只做一件事。业务逻辑超过 300 行考虑拆分。
2. **样式与逻辑分离**：所有 `StyleSheet` 必须放在 `styles.js` 中，`index.js` 只允许内联 **动态/条件样式**（如 `width: isDesktop ? "48%" : "100%"`）。
3. **禁止硬编码颜色**：所有颜色从 `styles/theme.js` 中的 `palette` 引入。新颜色先加到 palette 再使用。
4. **Props 解构**：函数参数直接解构 props，如 `function Example({ prop1, prop2 })`。
5. **默认导出**：每个 `index.js` 必须且只能有一个 `export default`。

### 2.3 App.js 开发规范

`App.js` 只负责：
- 顶层屏幕路由（screen state + 条件渲染）
- 全局共享状态（history、prefill 等）
- 全局持久化逻辑（localStorage 读写）
- 导航菜单（Header + Menu）

**禁止**在 App.js 中定义：
- 页面级业务组件
- 通用基础组件（Field、Metric 等）
- 任何页面私有样式

## 3. 样式规范

### 3.1 色板使用（palette）

```javascript
// styles/theme.js
export default {
  ink: "#151515",         // 主文字色
  muted: "#6d6d6d",       // 次要文字色/说明文字
  paper: "#ffffff",       // 页面背景
  panel: "#ffffff",       // 卡片背景
  line: "#e4e4e4",        // 边框/分割线
  accent: "#151515",      // 强调色（按钮背景）
  profitRed: "#d32f2f",   // 盈利色（红涨）
  lossGreen: "#0f7b55",   // 亏损色（绿跌）
};
```

**新增颜色流程**：先在 theme.js 中定义，再在组件 styles.js 中引入使用。

### 3.2 样式组织

- **组件私有样式**：放组件自己的 `styles.js`
- **通用布局样式**（如 flex 居中）：组件内局部定义，禁止新建不必要的全局样式
- **全局复用样式**（如页面容器）：放 `styles/global.js`（仅当多个页面同时使用时才提取）

### 3.3 命名规范

- style key：**小驼峰（camelCase）**，如 `primaryResult`、`historyItemTop`
- 语义化命名，不允许 `box1`、`text2` 这种无意义名字
- 推荐命名模式：`{组件/区块名}{作用}{状态?}`，如 `historyItem`、`segmentItemActive`

### 3.4 间距与尺寸

- 间距推荐用 4/8 的倍数：`4, 8, 10, 12, 14, 16, 18, 24, 32`
- 圆角：卡片 7~8px，胶囊按钮 999
- 输入框最小高度：46px（保证移动端点击区域）

## 4. 响应式布局规范

本项目同时支持 Web 桌面端、Web 移动端、原生 App。统一使用以下判断：

```javascript
const { width: screenWidth } = useWindowDimensions();
const isDesktop = Platform.OS === "web" && screenWidth >= 768;
```

- **桌面端（isDesktop = true）**：两列布局 `width: "48%"` + `gap: 24` + 居中 `maxWidth: 900`
- **移动端（isDesktop = false）**：单列布局 `width: "100%"` + `gap: 0`

响应式判断只允许在：
1. `App.js` 中传入各页面的 `isDesktop` prop
2. 各页面组件中根据 `isDesktop` 做动态内联样式

## 5. 数据持久化规范

### 5.1 localStorage 使用

- key 命名：`tradeHistory`（前缀项目名 + 语义）
- 仅在 `App.js` 中集中读写：
  - 初始化加载：`useState(loadHistory)`
  - 写入：统一通过 `addHistory` 函数，状态更新后立即 `setItem`
  - 清空：统一通过 `clearHistory` 函数，同步 `removeItem`
- 禁止在各子页面中直接操作 localStorage

### 5.2 数据格式

历史记录每条记录必须包含：
```javascript
{
  id: String,           // 唯一标识：Date.now + index
  time: String,         // 显示时间：MM-DD HH:mm
  screen: String,       // trade / contract / contractRoi / mt5Liquidation
  type: String,         // 股票 / 合约 / 止盈止损 / MT5强平
  title: String,        // 正T / 反T / 做多 / 做空
  isProfit: Boolean,    // 是否盈利（控制卡片边框颜色）
  summary: String,      // 摘要：如 "净利润 ¥123.45"
  detail: Array<{       // 详情列表
    label: String,
    value: String,
  }>,
  mode/side/form: Any,  // 原始表单数据（点击历史记录回填）
}
```

## 6. 导入路径规范

| 场景 | 导入示例 |
|------|----------|
| 同组件样式 | `import styles from "./styles"` |
| 同层兄弟组件 | `import Field from "../common/Field"` |
| 主题色板 | `import palette from "../../styles/theme"` |
| 工具函数 | `import { formatUsdt } from "../../utils"` |
| 计算逻辑 | `import { calculateTrade } from "../../calculator"` |
| App 内导入组件 | `import TradeCalculator from "./components/TradeCalculator"` |
| App 内导入样式 | `import styles from "./AppStyles"` |

**禁止**：
- 使用绝对路径别名（如 `@/components/...`），当前项目未配置
- 使用 `require()` 动态导入组件（计算逻辑可用）
- 循环导入

## 8. Git 提交规范

### 8.1 提交信息格式

```
<类型>: <简短描述>
```

类型：
- `feat`：新功能 / 新页面
- `fix`：修复 bug
- `refactor`：重构（如目录结构调整、组件拆分）
- `style`：样式调整（不影响逻辑）
- `docs`：文档变更
- `chore`：构建/配置/依赖相关

示例：
```
feat: 新增MT5强平价计算器
fix: 修复历史记录刷新后丢失问题
refactor: 组件按页面拆分文件夹，js/css分离
```

### 8.2 提交粒度

- 一个功能/修复一次提交，不要把多个不相关改动堆在一起
- 重构和功能修改分开提交
- 提交前自测：页面能否正常打开、切换、保存历史记录
